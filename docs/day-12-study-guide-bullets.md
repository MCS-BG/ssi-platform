# Day 12 study-guide bullets (FDE interview)

- **Same control plane, two substrates:** “I ran the SSI control plane — gateway, control-layer, business MCP, engineering MCP — on k3s in `si-lab`, then packaged the same Deployments with Helm for AKS without rewriting the agent loop.”
- **Enterprise edge, not a lab mesh:** “I mapped Tailscale Ingress (home-lab only) to Internal LB + Private Link + internal DNS for the SSI Connector base URL, and kept Tailscale out of the product story.”
- **Swappable model slot:** “I treated Ollama-on-GPU versus Azure OpenAI as a values-level model slot so the control-layer loop and Prompt Guard path stay stable when the customer’s model hosting choice changes.”
- **Bicep vs Terraform/OpenTofu, and why SSI leans portable:** “I wrote the same small AKS scaffolding (RG, AKS, ACR, Log Analytics, private DNS placeholder) in Bicep and in Terraform/OpenTofu, parameterized by location, name prefix, and Kubernetes version rather than a sprawling landing zone. Bicep is Azure-native with no state file and `what-if`, which is great for an all-Azure shop. Terraform/OpenTofu adds a state file to manage, but its `plan` workflow and providers carry to any cloud or on-prem. SSI’s pitch is that the customer owns the platform, so I default to open-source OpenTofu-compatible IaC with state in storage they control. The infra can move with them, and Bicep stays an option when they want Azure-native only.”
- **Fail-closed guardrails travel with the platform:** “Prompt Guard stayed fail-closed on AKS; the Helm chart does not dilute or bypass it, which is the same contract I proved on k3s.”
- **MCP topology customers own:** “Business and engineering MCP slots do not peer; they only cross-share through control-layer loop state — data-source agnostic, with D365 as one example backend, not a hard-wire.”
- **Secrets discipline:** “Gateway Bearer tokens are created as Kubernetes Secrets at deploy time (`ssi-gateway-auth`); nothing secret lands in git, Bicep params, or Helm values committed to the repo.”
- **Quiet observability lane:** “Grafana and Langfuse remain the quiet obs path (or Azure Monitor plus Langfuse); I only touch those endpoints when a step actually moves them, and I never put obs inside the agent loop.”
